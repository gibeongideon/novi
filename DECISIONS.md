| D-14 | 2026-11-11 | **JSON-2 envelope (verified in source, `odoo/http/dispatcher.py` Json2Dispatcher):** body is a flat JSON object of named arguments (`ids`, `context`, method kwargs; no positional args), response is the raw JSON result, errors are the serialised exception (`name, message, arguments, context, debug`) with a real HTTP status (UserError 422, AccessError/AccessDenied 403, MissingError 404, LockError 409, bad key 401). | D-15 | 2026-11-11 | **2FA login without Odoo changes (P0.10 outcome):** `POST /web/session/authenticate` with the password leaves `pre_uid` in the session and returns `uid: null`; the gateway then reads the CSRF token from the stock `/web/login/totp` page and posts `totp_token` to it, which finalises the session (`JsonRpcTransport.completeTwoFactor`). Verified live against Odoo 20 (contract test, ~1.2 s). No password-form scraping and no redirect fallback needed. Trusted devices verified too (`td_id` cookie, stored per user in the gateway vault); **the gateway must forward the end user's real User-Agent**, because Odoo names the device from it and returns 500 for unparseable UAs. | Keeps 2FA working for every tenant with zero install | Accepted |
| D-16 | 2026-11-11 | **Provisioning approach validated (P0.11 outcome):** own PG role + database (`REVOKE ALL … FROM PUBLIC`), own filestore volume, module init with the Odoo CLI in a one-off container, own Odoo container, admin/company bootstrap via ORM. Measured locally: **160 s total** (module init 152 s for 8 apps; everything else < 10 s), idle RAM **158 MB**, DB **70 MB**. Isolation verified: a tenant role can't read another tenant's tables, the instance only serves its own DB, the DB manager is disabled (create → 403), `admin/admin` no longer works. Teardown leaves nothing behind. **For P1.4:** also `REVOKE CONNECT ON DATABASE <every db> FROM PUBLIC`; to beat the module-init time, keep a pre-initialised template DB per plan and `CREATE DATABASE … TEMPLATE` (seconds instead of minutes). | Meets the < 5 min target with room to improve | Accepted |
| D-17 | 2026-11-11 | **Odoo 20 behaviours the engine/gateway must respect (found in Phase 0):** (1) Odoo listens on `127.0.0.1` by default, so containers need `http_interface = 0.0.0.0`; (2) websocket `subscribe` needs `check_outdated` in the payload, and `Origin` host must equal `Host` or the socket is downgraded to a public session, so the gateway relay must rewrite Origin; (3) the CSRF token for `type="http"` POST routes (`get_definitions`, upload, export, logout) is only in the `/odoo` page, so the client fetches and caches it; (4) `web_read` silently drops missing ids (returns `[]`); (5) Enterprise adds view types not in the plan (`map`, `hierarchy`, `gantt`, `cohort`, `grid`), which go to the scanner backlog / iframe fallback. | Avoid rediscovering these in later phases | Accepted |
| D-18 | 2026-11-11 | **Template databases for provisioning (implements the D-16 follow-up).** One frozen template per (plan, country), built once: base, then the company country, then the plan modules, so `account` picks the right localisation (KE → `l10n_ke` incl. eTIMS). After the build, the template role is `NOLOGIN` and the DB is `IS_TEMPLATE, ALLOW_CONNECTIONS false`. Sign-up = `CREATE DATABASE … TEMPLATE` → `REASSIGN OWNED BY novi_tpl TO tenant_x` → new `database.uuid`/`database.secret`/`create_date`, drop `web.base.url` → copy the template filestore → start → bootstrap admin. **Measured: 13.4 s and 8.3 s** (was 160 s); clone 2.7 s, filestore 2.7 s, start 5.7 s, bootstrap 2.3 s. Verified: unique secrets per tenant, 0 objects left owned by the template role, the template can't be connected to, tenants can't even CONNECT to each other's DB, 134 KE accounts in KES, cloned attachments served. Templates must be rebuilt when the Odoo image or plan modules change (provisioner job, P7.4.5). Slow install path stays as the fallback. **Security fix found in testing:** `REASSIGN OWNED` also moves *shared* objects (databases), and it had made the first tenant the owner of the template, which would have let it re-enable connections and poison future tenants. Template databases are now owned by the platform role (never `novi_tpl`), and sign-up aborts if `novi_tpl` owns any database or the template owner changes. Re-verified: 10.4 s / 9.0 s, template owner unchanged, clean teardown. **P1.4 must keep both guards.** | ~12× faster sign-up, correct localisation, stronger isolation | Accepted |

| D-26 | 2026-11-12 | **Gateway first slice = sign-in (same-domain mode).** The browser signs in through `POST /api/auth/login` + `/api/auth/totp` on the NOVI gateway, which runs Odoo's stock login and TOTP steps server-side and then hands the browser Odoo's own `session_id` cookie (plus `td_id` for remembered devices). Pending 2FA logins live server-side for 5 min, single use, behind an unguessable challenge id. The gateway forwards the user's real IP and User-Agent so Odoo's per-IP login cooldown keeps working and trusted devices are named correctly. The UI gets reason codes (`credentials`/`code`/`expired`) and shows NOVI's own translated messages. Engine has one `AuthClient` interface with gateway and direct-to-Odoo implementations. | D-27 | 2026-11-13 | **The gateway is a tenant-aware same-origin reverse proxy; the session vault is deleted** (Musk steps 1–2; supersedes the "gateway session vault" mechanism of D-03, keeps its goal). Every tenant host (`acme.novi.app`, a custom domain, or `acme.localhost` locally) points at the gateway, which resolves the tenant from the Host header (file-backed registry, D-10 instances), serves the web app, handles sign-in (D-26), and reverse-proxies the Odoo routes the app uses, websocket included, to that tenant's own Odoo. The browser therefore always talks to one origin and keeps Odoo's own HttpOnly `session_id` for that host. No vault, NOVI JWT or encryption keys are needed, and same-domain and separate-domain hosting become one code path. Verified: acme/beta created from the template in ~10 s each; each signs in only with its own users; a session from one tenant is rejected by the other and by the demo; live notifications flow through the gateway. Dev uses the same path (Vite → gateway). | One mechanism instead of two; fewer secrets; isolation by host | Accepted |
