| D-15 | 2026-11-11 | **2FA login without Odoo changes (P0.10 outcome):** `POST /web/session/authenticate` with the password leaves `pre_uid` in the session and returns `uid: null`; the gateway then reads the CSRF token from the stock `/web/login/totp` page and posts `totp_token` to it, which finalises the session (`JsonRpcTransport.completeTwoFactor`). | D-17 | 2026-11-11 | **Odoo 20 behaviours the engine/gateway must respect (found in Phase 0):** (1) Odoo listens on `127.0.0.1` by default, so containers need `http_interface = 0.0.0.0`; (2) websocket `subscribe` needs `check_outdated` in the payload, and `Origin` host must equal `Host` or the socket is downgraded to a public session, so the gateway relay must rewrite Origin; (3) the CSRF token for `type="http"` POST routes (`get_definitions`, upload, export, logout) is only in the `/odoo` page, so the client fetches and caches it; (4) `web_read` silently drops missing ids (returns `[]`); (5) Enterprise adds view types not in the plan (`map`, `hierarchy`, `gantt`, `cohort`, `grid`), which go to the scanner backlog / iframe fallback. | Avoid rediscovering these in later phases | Accepted |

| D-27 | 2026-11-13 | **The gateway is a tenant-aware same-origin reverse proxy; the session vault is deleted** (Musk steps 1–2; supersedes the "gateway session vault" mechanism of D-03, keeps its goal). Every tenant host (`acme.novi.app`, a custom domain, or `acme.localhost` locally) points at the gateway, which resolves the tenant from the Host header (file-backed registry, D-10 instances), serves the web app, handles sign-in (D-26), and reverse-proxies the Odoo routes the app uses, websocket included, to that tenant's own Odoo. No vault, NOVI JWT or encryption keys are needed, and same-domain and separate-domain hosting become one code path.
